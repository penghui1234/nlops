📋 工作流程说明

  1. 1
    入口接收:用户通过飞书 @机器人/Quick Desktop 发起请求, 或 CW Alarm 触发后通过 SNS 发送消息,或 DOA Investigation 完成后通过 EventBridge 通知。
  2. 2
    路由分发:Orchestrator Lambda 根据事件类型路由到不同 handler。 飞书事件采用异步两段式(立即返回 200 + Lambda 自调用处理), 满足飞书 3 秒 ack 要求。
  3. 3
    AI 调查:调用 devops-agent 启动 Investigation。 DOA 自主跨源关联 CloudWatch、Logs、X-Ray、GitHub 等数据源, 应用预置 Skills(ECS / RDS / Lambda 故障排查指南)。
  4. 4
    结果存储:渲染 HTML 诊断书上传 S3 (永久公开 URL), 审计日志写 DynamoDB AuditTable (90 天 TTL)。 Nova Pro 增强:故障公告 + SRE 摘要 + 自动 Skill markdown。
  5. 5
    通知 + 自动化:SES 发邮件,Lark Webhook 推群消息卡片。 高风险变更触发 SSM Automation Runbook (默认 dry-run)。 CloudWatch Logs 全程审计。IAM 最小权限保障。
  6. 6
    DOA 反向调用:DOA 通过 IAM AssumeRole 反向访问客户资源 (EC2/ECS/RDS/ALB/X-Ray/Config/CloudTrail) 进行跨源关联分析。 数据不离开客户 AWS 账户。
