1️⃣ 客户问题

某客户迁移 100+ 微服务到 AWS，大量使用 ECS / ALB / Lambda / RDS / ElastiCache 等托管服务。SRE 团队对 AWS 服务运维经验不足，希望快速完成问题定界定位，并逐步积累 AWS 运维经验。

🔍 信息分散

指标、日志、事件分散在多个 AWS 控制台
切换上下文耗时，关联难度大

🧠 经验难传承

资深工程师离职即失去关键经验
新成员需数月才能独立处理生产问题

⏱️ 定位耗时长

人工排障平均 1-2 小时
夜间告警尤其依赖随时在场的工程师

📱 移动端缺位

AWS 控制台不适合手机操作
值班工程师离开电脑就无法处理

4️⃣ AWS DevOps Agent 简介

实现卓越运营的前沿代理 — DOA 是 AWS 于 2026-03 GA 的自主运维 AI， 24/7 跨多云、多工具自动调查，提供根因和修复方案。

🔔 告别频繁报警

持续进行事件分诊，提供引导式解决方案，团队高枕无忧

🚀 主动卓越运营

从被动应对转向主动实现卓越运营,不再 7×24 救火

🔌 多源观测集成

支持 Dynatrace · New Relic · Datadog · Splunk · CloudWatch

🗺️ 智能资源映射

智能映射资源拓扑,提高 MTTR 和应用程序可靠性

5️⃣ DevOps Agent 6 大原生能力

AWS 原生的智能运维助手,通过自然语言交互,帮工程师快速调查生产问题、探索基础设施、处理优化建议、生成可视化报告。

🔍 调查问题

完整的问题调查生命周期管理
  • 创建调查 — 针对告警/异常发起结构化任务
  • 查看状态 — 实时跟踪进度,获取关键发现
  • 发送指导 — 注入上下文,引导聚焦方向
  • 处理缓解计划 — 自动生成,支持审核执行

🏗️ 探索基础设施

全维度资源感知与系统认知
  • 资源发现 — 枚举 EC2/Lambda/RDS/ECS,按标签过滤
  • 拓扑分析 — 服务间依赖与调用链路可视化
  • 指标分析 — CW 趋势分析与异常检测
  • 日志搜索 — 跨服务全文检索

💡 处理建议

聚合优化建议,按类别分类呈现
  • 浏览建议 — 成本/性能/安全/可靠性分类
  • 分析建议 — 评估影响范围与优先级
  • 接受建议 — 一键触发自动化执行
  • 拒绝建议 — 记录原因,标记不适用

📈 可视化报告

将调查结果生成结构化可视化报告
  • 图表 — 折线图(趋势) + 柱状图(对比)
  • 表格 — 资源清单/错误汇总/配置差异
  • 拓扑图 — 服务依赖 + 健康状态

🔀 代码变更分析

对接 GitHub PR 发布前后深度分析
  • 发布影响分析 — 识别涉及的服务与配置
  • 风险识别 — DB Schema/权限/依赖升级
  • 关联上下文 — 变更 + 指标 + 告警全链路

⚙️ Skills 管理

自定义技能(Skills) 把团队经验封装为可复用包
  • 创建技能 — 调查流程封装为 markdown
  • 配置技能 — 触发条件/参数默认值
  • 共享技能 — 团队内共享,标准化操作

🌟 核心能力 1：智能诊断

"用户说一句话 → DOA 跨源关联分析 → HTML 诊断书 → 邮件/IM 通知"

1
飞书 @机器人提问 / 凌晨告警自动触发
2
DOA 自主决定调用哪些工具:CloudWatch / Logs Insights / X-Ray / GitHub deployments / Skills 历史经验
3
5-15 分钟 AI 自主跨源关联,识别根因 + 时间线 + 因果链
4
EventBridge 通知 NLOps Lambda → 渲染 HTML 诊断书 → 推送 IM/邮件

🌟 核心能力 2：HTML 诊断书

不是 Dashboard,是 AI 诊断书 —— 类比传统 Dashboard 是"体检数值表",NLOps 诊断书是"医生写的诊断报告"。

📊 数据图表

ECharts 趋势线 + 拓扑图 + 火焰图,带告警阈值标记

📝 AI 文字解读

"CPU 在 14:32 异常上升,与部署 commit abc123 时间关联"

🔗 因果分析

时间线 + 关联事件 + 依赖链路

💡 操作建议

"建议扩容 RDS Proxy 连接池 200→400 (调用 SSM Runbook)"

📎 证据链

日志片段 + Trace ID + 部署记录 + DOA 用过的工具

📣 故障公告

AI 自动生成中文公告,直接发布到状态页

生成流程

1
DOA Investigation 完成 → ListJournalRecords 抓 AI 完整 markdown 报告
2
Nova Pro 增强:生成公告/SRE摘要/自动 Skill
3
Jinja2 模板渲染 (含 marked.js + ECharts CDN)
4
上传 S3 → 永久公开 URL (bucket policy 仅 /reports/* 公开)

🌟 核心能力 3：告警自动闭环

凌晨告警 → Webhook + HMAC → DOA 自动调查 → 飞书 + 邮件双通道 + HTML 诊断书

1
CW Alarm 触发 — CloudWatch 告警进入 ALARM 状态
2
SNS → Lambda — Webhook Forwarder 解析告警内容,转 DOA
3
DOA 自动调查 — Investigation 启动 (5-15 min),自动应用相关 Skills
4
EventBridge 回调 — source=aws.devopsagent + Investigation Completed
5
渲染诊断书 — GetBacklogTask + ListJournalRecords → Jinja2 → S3 永久 URL
6
双通道通知 — 飞书群消息卡片(红/橙/黄) + SES HTML 邮件

📧 SRE 收到的邮件包含:告警标题 + 严重度 + 中文根因摘要 + HTML 诊断书链接 + 修复建议 + 证据链

🌟 核心能力 4：经验自动沉淀

每次故障处理完成后,自动从 AI 报告提取根因+处理流程,生成新 Skill。下次相似问题 DOA 自动应用此经验,秒级出方案。

经验闭环流程

1
故障处理完成 — DOA Investigation 完成,有完整 markdown 报告
2
提取关键信息 — Nova Pro 自动提取:根因 + 修复步骤 + 时间线 + 证据
3
生成 Skill markdown — 按 DOA Skill 模板生成,含 frontmatter (name/description/触发条件)
4
上传到 S3 — skills/auto/<name>-<timestamp>.md
5
下次相似问题 — DOA 调查时自动匹配相关 Skill,应用历史经验
