1️⃣ 客户问题

某客户迁移 100+ 微服务到 AWS，大量使用 ECS / ALB / Lambda / RDS / ElastiCache 等托管服务。SRE 团队对 AWS 服务运维经验不足，希望快速完成问题定界定位，并逐步积累 AWS 运维经验。

🔍 信息分散

指标、日志、事件分散在多个 AWS 控制台
切换上下文耗时，关联难度大

🧠 经验难传承

资深工程师离职即失去关键经验
新成员需数月才能独立处理生产问题

⏱️ 定位耗时长

人工排障平均 1-2 小时
夜间告警尤其依赖随时在场的工程师

📱 移动端缺位

AWS 控制台不适合手机操作
值班工程师离开电脑就无法处理

2️⃣ 客户要什么

💬 自然语言交互

不学新工具，一句话完成排障
中文/英文都行，IM/语音/桌面都行

📊 给结论不给数字

不要 Dashboard 数字罗列
要 AI 解读 + 修复建议 + 证据链

🌙 夜间无人值守

凌晨告警自动调查
醒来时已经知道根因，而不是被叫醒

🧬 经验自动沉淀

处理过的问题下次自动复用
团队经验越积越多，新成员快速上手

3️⃣ 业界方案对比

方案类型代表产品做法弊端
传统监控 CloudWatch / Grafana / Zabbix Dashboard 展示 给数字不给结论
AIOps 平台 Datadog Bits AI / Dynatrace Davis AI 根因分析 + 修复建议 绑定自有生态，月成本 $44-118/host
AWS 原生 AWS DevOps Agent (2026-03 GA) 自主调查 + 跨平台关联 + 详细修复计划 可视化输出偏控制台技术视角，缺中国 IM 入口
NLOps v4 (我们) AWS DOA + 飞书/Quick + HTML 诊断书 + Skills DOA 引擎 + 中国化体验层 + 自动经验沉淀 —

5️⃣ 核心能力（已实现）

🔍 智能诊断

用户飞书 @机器人一句话 → DOA 自主跨源关联 (CW + Logs + X-Ray + GitHub) → 5-15 分钟出根因
Lark Bot DOA Investigation 异步处理

📊 HTML 诊断书

不是 Dashboard，是 AI 诊断报告。含 AI 解读、ECharts 趋势图、工具使用、操作建议、证据链
Jinja2 marked.js ECharts S3

🚨 告警自动闭环

CW Alarm → SNS → Lambda → DOA 自动调查 → 飞书卡片 + 邮件双通道
CloudWatch SNS EventBridge SES Lark Webhook

🧬 经验自动沉淀

每次 Investigation 完成后，Nova Pro 自动提取根因+步骤生成 Skill markdown，下次相似问题秒级匹配
Nova Pro DOA Skills S3

📣 故障公告自动化

AI 自动生成两版文案：面向用户的中文公告 + 面向 SRE 的内部摘要（含行动项）
Nova Pro Bedrock

⚙️ MCP 工具盒

5 个标准 MCP 工具，任何 MCP-aware AI（Quick/Claude/Nova）都可调用
JSON-RPC 2.0 API Gateway stdio bridge

6️⃣ 演示场景

Demo 1: 飞书智能问诊（主动）

1
用户在飞书群 @NLOps demo-api 服务为什么慢？
2
机器人 3-5 秒回复：🔍 已启动深度调查 task_id: xxx-xxx，预计 5-15 分钟完成
3
DOA 自动应用 ECS Skill，跨源关联 CloudWatch + GitHub 部署历史
4
调查完成 → 飞书群自动收到红色卡片（根因+诊断书按钮）
5
点击按钮 → 浏览器打开图文并茂的 HTML 诊断书（含趋势图、AI 报告、自动 Skill 提示）

Demo 2: 凌晨告警闭环（被动）

1
CW Alarm 进入 ALARM 状态（凌晨 2 点 SRE 在睡觉）
2
SNS → Lambda → DOA 自动启动 Investigation（无人干预）
3
DOA 完成调查 → EventBridge → Lambda 渲染诊断书
4
早上 SRE 起床 → 飞书已有完整调查卡片 + 邮箱已有故障公告草稿（直接发布即可）
