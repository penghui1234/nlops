> "先看客户场景。某客户迁移了 100+ 微服务到 AWS，使用了大量 ECS / ALB / Lambda / RDS / ElastiCache。但 SRE 团队对 AWS 运维经验不足，遇到 4 大痛点：

## 🎬 Demo 2: 凌晨告警自动闭环（4 分钟）

**【切到 PPT 翻到 Demo 2 页】**

> "Demo 2 是被动场景。**假设凌晨 2 点 demo-api 高 CPU，SRE 在睡觉**。我现在按一下按钮触发告警，看完整闭环。"

**【打开终端，执行】**：
```bash
aws cloudwatch set-alarm-state \
  --alarm-name demo-api-high-cpu \
  --state-value ALARM \
  --state-reason "[demo] CPU spike on demo-api EC2" \
  --region us-east-1
```

> "好，告警触发了。这个告警进入 ALARM 状态后，会发到 SNS Topic，触发我们的 Lambda。"

**【切到 CloudWatch Logs 标签查看实时日志】**

> "看 Lambda 日志，已经收到 SNS 消息，开始调用 DOA start_investigation。"

**【等 30 秒 + 转换叙述】**

> "实际生产中 DOA 调查需要 5-15 分钟。**关键时刻是凌晨 2 点 SRE 在睡觉，醒来时已经知道根因**。我们看下 SRE 早上会收到什么。"

**【切到飞书群标签 + 邮箱标签（用之前测试的卡片/邮件）】**

> "看，飞书群里有一条红色的紧急告警卡片。包含：根因摘要、Investigation ID、查看诊断书按钮、DOA Operator 链接。

> 邮箱也收到了 HTML 邮件。注意这一段 —— **'故障公告草稿'，AI 自动生成的中文用户公告，可以直接发布到状态页**。这是 v4 的新能力，用 Nova Pro 做的。"

## 🎬 Q&A 常见问题应对（参考 CHEAT-SHEET.md）

详细 10 个常见问题答案见 `CHEAT-SHEET.md`。

### 高频追问准备
- **"如果 DOA 服务挂了怎么办？"** → CW Investigations 降级 + 邮件告警
- **"中国客户什么时候能用？"** → Phase 5（约 2027），中国区 CW Investigations 现已可用
- **"飞书机器人会泄露内部信息吗？"** → 飞书 App 仅有限权限，事件订阅签名验证
- **"诊断书 URL 公开读会不会被爬？"** → URL 含 UUID + 时间戳，外部猜不到；可以加 CloudFront OAC 加固
- **"这个项目能开源吗？"** → 当前是内部演示，正式开源需 legal review

### 演示翻车应急（按严重度）

| 翻车 | 应对 |
|------|------|
| 单个按钮不工作 | 跳过，"这个我们再调一下，看下一个" |
| 整个 Demo 不工作 | 切到 backup 视频 / PPT 截图："为节省时间用预录的" |

| AWS 控制台卡 | 永远不要打开 AWS 控制台！全程用我们自己的界面 |
