痛点 + 业界 + 需求

2客户的问题✅
  • 某客户迁移 100+ 微服务到 AWS，大量使用 ECS/ALB/Lambda/RDS/ElastiCache
  • SRE 团队对 AWS 服务运维经验不足，希望快速定界定位并积累经验
  • 运维现状：主动逐一看 CW / 被动切换多控制台
  • 团队现状：依赖对 AWS 熟悉的工程师 / 经验无法沉淀
  • 痛点：上下文丢失 / 知识无法传承 / 指标多看不懂 / 定位耗时 / 值班不在电脑旁
3问题的挑战（技术难点）✅
  • ❶ 多源数据关联 — 指标+日志+链路+变更散落不同服务
  • ❷ 指标体系庞大 — ECS 几十个指标不知道看哪个
  • ❸ 根因跨服务 — A 慢可能是 B 导致的
  • ❹ 操作高风险 — 扩容/重启影响面大
  • ❺ 知识自动沉淀 — 非结构化经验如何变成可检索知识
4业界方案（含弊端）✅
  • 传统监控（CW/Grafana）→ 给数字不给结论
  • ChatOps（AWS Chatbot/PagerDuty）→ 无推理能力
  • AIOps 平台（Datadog Bits AI / Dynatrace Davis AI）→ 绑定自有生态 $44-99/host
  • AI Agent 框架（LangChain / CrewAI）→ 通用框架，无 AWS 运维深度集成
  • AWS DevOps Agent (2026-03 GA) → ✅ 分析最强(94%)，但纯文字/无写护栏/无中文IM/经验沉淀不可控
💡 DevOps Agent 是最强引擎（94% 准确率、MTTR -75%），但缺驾驶舱。NLOps = 驾驶舱。
5客户要什么✅
  • 主动巡检 — 快速获得系统健康全貌
  • 被动响应 — 快速定界→定位→修复
  • 夜间 on-call — 不开电脑也能了解情况
  • 新人上手 — 不依赖个人经验也能处理常见故障
→ 用自然语言完成运维全流程，随时随地
6解决方案✅
  • 基于 AWS DevOps Agent，构建体验层 + 安全层 + 经验层
  • 流程：自然语言输入 → 发现分析 → 诊断书输出(+SES邮件) → 安全执行 → 经验沉淀
  • 金句：多入口 · 自然语言驱动 · 可视化诊断书 · 智能闭环 = 随时随地、开口即运维
  • 定位：DevOps Agent 做引擎，NLOps 做驾驶舱

架构

7整体架构待做
  • 四层：交互层 → AI 编排层 → AWS 服务层 → 存储层
  • 交互层：输入自然语言 ｜ 输出 HTML 诊断书+邮件 · Quick Desktop / 企微飞书(v4)
  • AI 编排层：Strands Agent (自动路由) + 5 @tool（discover_service / deep_investigate / search_knowledge / render_report / request_execute）
  • AWS 服务层：DevOps Agent · Bedrock Nova Pro · CloudWatch · EventBridge · SES · SNS
  • 存储层：S3（HTML+KB沉淀）· DynamoDB ×3（Sessions/Audit/Tokens）
  • 21 个 MCP 工具盒：任何 MCP-aware AI（Quick Desktop / DOA / Cursor）都能调用
8AWS 部署图待做
  • 带 AWS 官方图标的部署视图（draw.io 导出）
  • L1 OrchestratorFn（1536MB, Strands SDK）+ L2 ExecutionFn（512MB, 写隔离）
  • API Gateway ×2 · EventBridge · Bedrock · DOA · S3 · DDB×3 · SES · SNS
  • 3 条集成路径标注：call-down / event-up / mcp-out（mcp-in 标 v4 计划）
  • 关键数字：Lambda:2 · MCP 工具:21 · Strands @tool:5 · AWS 服务:~14 · CDK ~15min · Region: us-east-1
  • 构建依赖：Strands Lambda Layer（pip install → zip → CDK 自动上传）

核心能力 ×5

9核心能力①：智能诊断（Strands + DOA）待做
  • smart_diagnose: 1 句话触发 Strands Agent → 5 Tool 协作 → DOA → HTML
  • consult_devops_agent: 直调 DOA chat (5-30s) — CreateChat + SendMessage
  • DOA Investigation (5-15min) — CreateBacklogTask → EventBridge 异步通知
  • 降级：DOA 不可达 → CloudWatch 直连 fallback
  • Strands SDK 1.40 (AWS 开源) vs LangChain：原生 Bedrock 支持 + MCP 兼容 + 轻量
10核心能力②：HTML 诊断书待做
  • 不是 Dashboard，是 AI 诊断书 — 5 要素：图表 + AI解读 + 因果分析 + 操作建议 + 证据链
  • 生成流程：Agent 分析 → LLM 生成 JSON → Jinja2 模板渲染 → S3 → Presigned URL（30天）
  • SES HTML 邮件：内联 CSS，手机友好，Quick Suite Email Connector 可索引
  • 类比：传统 Dashboard = 体检数值表；NLOps 诊断书 = 医生写的诊断报告
11核心能力③：写操作护栏待做
  • ❶ 意图结构化 — Strands Agent 解析为 {type, params}
  • ❷ Policy Guard — Agent 级权限矩阵，早拦截
  • ❸ Confirm Token — request_confirm_token 工具，5 分钟单次有效，session+user 绑定
  • ❹ L2 独立 IAM — ExecutionFn 独立 Role，tag 边界 nlops:managed=true
  • ❺ 审计日志 — AuditTable 全量记录，90 天 TTL
  • 设计原则："读全在 L1，写隔离 L2" — 即使 L1 被 prompt injection 也写不了 AWS 资源
12核心能力④：告警自动闭环待做
  • CW Alarm → DOA 自动 Investigation → EventBridge (aws.aidevops) → L1
  • L1 自动：渲染 HTML 诊断书 → S3 + SES HTML 邮件 + Bedrock KB 双写 + SNS
  • 全程无人工 · SRE 醒来时方案已在邮箱
💡 全程无人工 · SRE 醒来时方案已在邮箱
13核心能力⑤：经验沉淀（Bedrock KB）待做
  • 每次故障处理完自动沉淀到 Bedrock KB（S3 JSON → ingestion → 向量化）
  • 下次相似问题 → search_knowledge → 语义检索 Top-K（Titan Embed v2）
  • AuditTable 5 条真实 incident 已预置（可演示 list_investigations）
  • 效果：30min MTTR → 2min（匹配成功时）
  • 注：DOA Custom Skill 无 SDK API → 走 Bedrock KB 双写路径
